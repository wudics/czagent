# 风险与对策

> 覆盖 I0–I6 及 P2 的主要技术风险，按严重程度排序。

## R1. 原生模块在国内的安装/下载失败（高）

- **表现**：better-sqlite3 / electron 二进制 / electron-builder 资源从 GitHub 下载超时或失败，`pnpm install` / 打包中断。
- **对策**：`.npmrc` 配置 npmmirror 镜像（packaging.md §3）；postinstall 增加下载失败提示与镜像兜底；CI 预缓存。
- **验证**：I0 阶段在干净环境跑通 `pnpm install` + `pnpm dev`。

## R2. 国内搜索引擎爬虫脆弱（高，P2）

- **表现**：页面结构变动、反爬（验证码/UA 检测）、编码乱码、结果不完整。
- **对策**：多引擎独立解析器 + 降级；请求节流（≤1 次/2s）+ 合理 UA；解析容错（提取不到即跳过）；失败静默降级并提示"搜索不可用，可改用 webfetch 直达 URL"。
- **验证**：websearch 单测用录制样本 + 真机抽样比对三引擎。

## R3. 长会话上下文质量（中）

- **表现**：1M 上下文模型下，基于 `chars/4` 的估算与实际 token 偏差大，压缩触发时机不准；压缩摘要可能丢失关键信息。
- **对策**：压缩阈值/保留窗口/输出截断全可配；摘要 prompt 强调"保留 Objective/关键细节/工作状态/下一步"；支持用户手动触发压缩；溢出重跑仅 1 次防死循环。
- **验证**：构造 100+ 轮对话压力测试，人工检查摘要完整性与续聊正确性。

## R4. DeepSeek 工具场景 reasoning_content 回传规则（中）

- **表现**：带 `tools` 的请求若 assistant 消息未回传 `reasoning_content` → 400。
- **对策**：协议层强制：凡请求含 tools 且历史含 reasoning part，转 `role:assistant` 消息时必带 `reasoning_content`；协议测试覆盖该场景。
- **验证**：三家各跑一次"带工具调用的多轮对话"冒烟。

## R5. 虚拟滚动 + 流式 + 自动滚动的边界交互（中）

- **表现**：流式高频更新 + 动态高度测量 + 用户中途滚动，可能出现跳动/自动滚动误判/分页锚点漂移。
- **对策**：I1 用 Mock 模拟流式充分打磨交互；自动滚动用"距底阈值 + 用户主动滚动标记"判定；分页用 beforeId 锚点 + `scrollToIndex`；新增消息期间冻结测量避免跳动。
- **验证**：Mock 下 1000 条消息滚动流畅、一键到底准确、查看历史时不被拽走。

## R6. 多会话并发下的资源竞争（中）

- **表现**：多会话同时跑 LLM + 终端 + 写库，可能互相拖累（限流 429、sqlite 写放大、pty 数量膨胀）。
- **对策**：并发上限默认 4 可配；LLM 重试尊重 retry-after；sqlite 写去抖合并；pty 按会话复用；事件总线不阻塞主循环。
- **验证**：4 会话同时长任务 + 边跑边切换会话 UI，观察响应与内存。

## R7. pnpm + Electron/native 打包坑（中）

- **表现**：symlink 导致 Electron 找不到二进制 / 原生模块 `.node` 未打进 asar / asar 内不可加载原生模块。
- **对策**：`.npmrc` hoist 配置；asarUnpack 白名单；打包后 smoke test；`electron-builder --dir` 本地验证后再出安装包。
- **验证**：I0 与每轮迭代末尾执行打包 smoke。

## R8. 各家协议差异导致的兼容面（中）

- **表现**：SiliconFlow 错误体为纯字符串、Agnes `extra_body` 约定、DeepSeek Responses 无 `[DONE]`、图片响应结构不一致等。
- **对策**：差异全部收敛到 profile 层；协议引擎对上层暴露统一接口；每家写协议级单测（用录制响应做 golden test）。
- **验证**：三家 chat 流式 + 工具调用 + 错误路径各一组单测。

## R9. 权限边界被绕过（高，安全）

- **表现**：符号链接 / 大小写 / `..` 路径穿越使 cwd 外路径被当成 cwd 内。
- **对策**：路径一律 `realpath` 归一化后比较；bash 正则黑名单 + 危险命令确认；权限判定集中一个函数并单测覆盖（symlink、大小写、`..`）。
- **验证**：工具权限单测注入恶意路径样本。

## R10. P2 范围膨胀（中）

- **表现**：脚本编排、websearch、skill、MCP、多模态同时铺开，导致 P1 质量稀释。
- **对策**：严格执行迭代计划，P1 只做承诺范围；每轮末用户验收通过才进入下一轮；P2 按依赖排序（编排 → 搜索 → skill → MCP → 多模态）。
