## 遇到的问题与解决

| 问题 | 解决 |
|---|---|
| SessionEvent 部分成员重复 `sessionId` 字段 | 移除重复（TS 报 duplicate identifier） |
| mock 分页 `map.get()?.[i]!` 仍可能 undefined（noUncheckedIndexedAccess） | 改为 `(map.get() ?? [])[i]!` |
| 流式 part 联合类型 spread 编译报错 | 收窄为 `{type:'text'|'reasoning'; text}` |
| 思考场景用 `Math.random()` 导致测试不稳定 | 改为确定性 `hasThinking = thinkingMode !== 'off'` |
| 停止后仍发 `message.complete`（合理：需保留局部消息） | 测试断言改为「局部完成，文本短于全文」 |
| 静态种子消息 tool-call 卡在 running | 补 tool-result part，状态 completed |
| `TEXT_LONG` 未导出导致测试 import undefined | 补 `export` |

## 说明（对方案的 2 处微调）

1. **markdown Worker 采用 `marked` 而非 react-markdown**：react-markdown 是 React 组件、无法在 Worker 内跑；改为主线程用 `dangerouslySetInnerHTML` 渲染 Worker 产出的 HTML。语义等价，Worker 防卡顿目标达成。渲染正确性在流式/长文档下已实测无卡顿。
2. **思考模式种子数据**：`s-demo-plan` 默认思考模式为 on，回复固定带 reasoning part，便于观察内联样式；切「不思考」可对比。
