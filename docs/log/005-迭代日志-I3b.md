## 目标

把临时模拟回复替换为**真实三家模型流式对话**：SSE 协议引擎 + 三家 profile + 最小 agent loop 接入 + 真实 usage 记账。

## 完成项

- [x] **协议引擎**（`core/src/llm/`）：
  - `sse.ts`：ReadableStream → `data:` 行逐条产出（过滤 `[DONE]`）
  - `types.ts`：`LLMChatMessage` + `LLMEvent`（reasoning-delta / text-delta / finish / error）+ `ChatStreamRequest`
  - `profile.ts`：三家 profile（baseURL/path/thinkingParams/reasoningField/reasoningPassthrough）+ 自定义厂商通用 profile
  - `client.ts`：`streamChat()` fetch + SSE 状态机 + 请求重试（429/5xx 指数退避 + retry-after，最多 2 次）+ `stream_options.include_usage`
  - `errors.ts`：`LLMError` 分类（auth/rate_limit/quota/invalid/context_overflow/provider/network/cancelled）+ `friendlyLLMMessage` 中文提示
  - `usage.ts`：usage 归一化（兼容 deepseek `prompt_cache_hit_tokens`、siliconflow `prompt_tokens_details.cached_tokens`）
- [x] **SessionManager 真实 turn**（替换 dev-mock-reply，已删除）：
  - 读取会话模型/provider/apiKey；未配置 → 友好错误 part
  - 历史消息（含 agent systemPrompt、DeepSeek `reasoning_content` 回传，R4）
  - 思考模式映射三家参数（决策 15）
  - 流式 parts 增量持久化 + finish 携带的**真实 usage** 记账 + 事件推送
  - 错误分类中文提示、用户停止保留已输出内容

## 遇到的问题与解决

| 问题 | 解决 |
|---|---|
| `ChatStreamRequest` 从 client.js 导入不存在 | 改从 `types.js` 导入 |
| client 内联错误分类漏了 context-overflow 检测 | 复用 `errors.ts: classifyHttpError`（400/413 时正则判定 context_overflow） |
| runTurn 未用 provider finish 的真实 usage（按文本估算） | 捕获 `finish.usage` → `providerUsage`，finalize 优先使用 |
| 测试共享 config 目录导致 apiKey 污染 | test 2（无 key 场景）改用独立临时目录 |
| runTurn 编辑时 try/catch 结构被破坏 | 整体重写该文件为干净版本 |
