## 遇到的问题与解决

| 问题 | 解决 |
|---|---|
| 写操作 cwd 内外都弹窗 | 根因：用户 `config.json` 是旧默认（build agent `ask` 含 write），`resolveWrite` 的「agent 显式规则优先」命中 ask。修复：写类工具**仅 allow/deny 生效，ask 一律交给路径感知**（cwd 内放行/外询问），对旧配置也鲁棒 |
| 写桌面不弹窗 | 根因：cwd=主目录时 `Desktop` 是子目录，`pathInside` 判为内部。经确认（子目录语义符合预期）**未改代码**；如需保护主目录特殊文件夹可后续加敏感路径黑名单 |
| apply_patch 纯插入 hunk 静默丢失 | 增强解析器：解析 `@@` 行号 + 锚点插入 + 歧义报错 |

## 验收后修复（追加）

### Agnes maxOutput 默认值修正（67108 → 65536）
- **背景**：使用 agnes-2.5-flash 报「模型服务暂时异常，请稍后重试。」（= provider 5xx 分类）。Agnes 端点连通正常（401 with invalid key）；排查发现 settings-defaults 里 agnes-2.5-flash / agnes-2.5-pro 的 `maxOutput: 67_108` 超文档上限（65.5K / 65536），导致请求发 `max_tokens: 67108` 超限。
- **根因**：67108 为作者在 I2 创建默认模型目录时的笔误/臆测值（非文档来源，全库仅 settings-defaults.ts:14-15 出现），两模型复制粘贴同值。
- **修复**：`core/src/settings-defaults.ts` 两处 `maxOutput` 67_108 → 65_536。
- **验证**：用户改配置后 agnes-2.5-flash 恢复正常；typecheck/测试/build 全过。

### 添加模型未知 ctx/out 的处理（默认 0 = 未知）
- **现状**：`maxOutput: 0` → session-manager 不发 `max_tokens`（`model.maxOutput > 0 ? ... : undefined`），模型用默认上限，安全；`contextLimit: 0` 当前运行时未用。
- **改动**：
  - `ModelsTab.tsx`：addModel 默认 `contextLimit: 0, maxOutput: 0`（不再硬编码 131072/32768，避免 67108 类臆测值坑）
  - `ModelsTab.tsx`：ctx/out NumInput 加 placeholder「0=未知」+ title 提示「0 = 未知/不限制」
- **待办（I6b 压缩实现时）**：`contextLimit === 0` 必须视为「未知 → 不自动压缩」，否则 `usable = context - reserved` 算成 0 会每轮触发压缩。已在 I6b 计划中标注。

### bash 命令平台化（引导模型生成当前系统命令）
- **背景**：Windows 下 bash 工具执行层已用 PowerShell，但模型生成命令倾向 POSIX（ls/cat/rm/grep）导致失败。根因：工具 id 叫 bash + 描述笼统 + system prompt 未告知平台。
- **改动**：
  - `tools/bash.ts`：描述按 `process.platform` 生成——Windows 明示「使用 PowerShell 语法（Get-ChildItem/dir、Get-Content/type、Remove-Item/del、Select-String/findstr、反斜杠路径），不要用 Linux 命令」；Linux/mac 保持 POSIX 说明。描述随工具 schema 发模型。
  - `session-manager.ts`：请求 system 消息注入 `<env>`（当前系统平台+架构 / 会话工作目录 / 当前日期），对所有 agent 与工具生效，模型据此选命令与路径处理。
  - 工具 id 保持 `bash`，不破坏旧会话/配置。
- **测试**：bash 描述平台化断言；`<env>` 注入断言（system 含 `<env>`+平台+cwd）。
