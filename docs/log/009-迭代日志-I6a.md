## 验收后修复（追加）：内联附件误导模型 read

- **背景**：上传小 txt 内联后，消息前缀 `<file: pow.txt>` 让模型误以为工作目录下有该文件，调 `read C:\Users\wudics\pow.txt` → ENOENT（文件其实在附件 temp 目录且内容已内联）。
- **改动**：
  - `textToMessagePart`：内联格式改为 `<已上传附件: name（内容已内联，无需读取文件）>\n<文件内容开始>\n...\n<文件内容结束>`（不再出现 `file: name` 误导路径）。
  - `sendMessage`：附件降级为 file 引用（大文本/解析失败/无视觉图片）时，追加 text part `<已上传附件: name（...已存至 <storedPath>，可调用 read 读取该路径）>`，让模型能按真实路径读取。
  - `buildRequestMessages`：user 消息的 `file` part（历史重载）追加 `<附件: name（已存至 path，可 read 读取）>`。
- **测试**：内联格式断言（含"内容已内联，无需读取"、不含 `<file:`）；大文件引用含"已存至" + file part。
- **验证**：typecheck ✅ · 测试 75/75（3 连跑稳定）✅ · build ✅ · Electron 无渲染错误 ✅

### 备注：历史 image part 重放到非视觉模型的边界

- **现象**：旧会话中 deepseek（`vision:false`）报 `This model does not support image`；新会话正常。
- **根因**：`buildRequestMessages` **不区分当前模型是否有视觉**——若会话历史里残留带 `image` part 的消息（早期模型带视觉时内联、或其它路径产生），重放历史时会把图片发给 `vision:false` 的模型 → 400。
- **结论**：三档图片路由（视觉内联 / 图像理解描述 / 降级引用）本身正确；问题源于历史上下文中的 image part 被无条件重发。
- **加固（已实现）**：`buildRequestMessages` 增加 `includeImages` 参数（由 `model.vision !== false` 决定）；模型无视觉时，历史 user 消息的 `image` part **不发送**，替换为文本 `<图片附件已省略：当前模型不支持图片>`。覆盖"会话中途切模型（视觉→非视觉）/ 旧会话残留 image part"场景。
- **测试**：新增「无视觉模型 → 历史 image part 被省略并附说明」用例。
- **复现反馈**：修后图像理解路由正常（agnes 生成描述成功），但主链请求报 `Invalid assistant message: content or tool_calls must be set`。
- **根因（2 次修复）**：历史里残留**仅含 `error` part、无文本/推理/工具调用**的 assistant 消息（上一轮请求失败的残留），`buildRequestMessages` 序列化为 `{role:'assistant', content:null, toolCalls:undefined}` → deepseek 400。
- **修复（已实现）**：assistant 分支对「无文本 && 无推理 && 无 tool-call」的消息**直接跳过**（不产出空 assistant）；role:tool 只随 tool-call part 发出，不产生悬空。
- **测试**：新增「历史仅 error part 的 assistant 消息 → 请求中不含空 assistant」用例。
- **验证**：typecheck ✅ · 测试 87/87（core 79 + desktop 9）✅ · build ✅ · Electron 无渲染错误 ✅
