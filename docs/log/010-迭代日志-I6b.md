## 目标

上下文压缩：溢出检测 / 摘要 checkpoint / 工具输出截断 / overflow 重跑（`contextLimit===0` 不自动压缩）。

## 完成项

- [x] **估算模块**（`core/src/compaction.ts`）：`estimateTokens`（CJK 约 1.5 字/token、其余约 4 字符/token）；`estimateRequestTokens`（消息结构开销 4、工具条目 2、图片固定 2000 + base64 增量）；`truncateToolOutput`（3000 字符头部 + 截断标记）
- [x] **溢出检测**（runLoop 每轮）：`compactionUsable()` —— `contextLimit<=0`（未知）或 `auto=false` → 不自动压缩；`usable = contextLimit - reservedTokens`，`usable<=0` 同样跳过
- [x] **摘要 checkpoint**（`maybeCompact` + `summarize`）：溢出时把旧区折叠为摘要（用会话模型单次对话，与主循环相同请求规则——视觉模型摘要请求带图、非视觉不带；system 提示保留结论/决策/文件路径/图片相关内容/待办）；失败则本轮跳过（下轮再试）
- [x] **窗口**（`historyWindow`）：请求只从最后一个 compaction checkpoint 起（含），压缩摘要以 `system` 消息置于请求头部（`buildRequestMessages` 识别 compaction part）；被压缩旧消息**完整保留在 DB**（非破坏，UI 可翻页）
- [x] **保留尾部**：`keep = max(1, ⌈preserveRatio×总数⌉)` 条最新消息逐字保留（含最新 user 消息）；checkpoint 的 createdAt 取 keep 最旧一条 -1ms，保证排序位于 old 与 keep 之间
- [x] **工具输出截断**：`buildRequestMessages` 的 `role:tool` content 经 `truncateToolOutput`（仅请求侧，DB 存全量；大文件读取可再次 read）
- [x] **overflow 重试（≤1 次）**：压缩后仍超限 → 丢弃最旧一条（跳过摘要 checkpoint）再试一次；仍超限则原样发送（尽力而为）

## 附件 × 压缩 的处理约定

| 附件类型 | 进入请求的形式 | 被压缩后 |
|---|---|---|
| 图片 + 视觉模型 | `image` part（base64，估算 2000+/张） | 折叠进摘要；摘要可含视觉结论（摘要请求带图）；原图保留 DB/UI |
| 图片 + 非视觉模型 | 图像理解描述文本 | 作为普通文本参与摘要 |
| 文本 ≤50KB 内联 | 内联 text part | 按文本 token 参与估算；压缩后仅摘要提及 |
| 文本 >50KB 引用 | 文件路径提示（可忽略大小） | 摘要 prompt 要求保留**路径**，模型日后可 re-read |
| 工具读文件结果 | `tool-result`，请求侧截断 3000 字符 | 超长部分只在请求中省略；DB 全量 |

## 边界与后续

- 估算为启发式（CJK/1.5 + ASCII/4 + 结构开销），非精确 tokenizer；以 `reservedTokens` 缓冲兜底，后续可按平台精确化。
- 摘要失败（模型异常）→ 本轮跳过，下轮重试；不会进入压缩死循环。
- 压缩后视觉图片的原始视觉信息仅在摘要文本中（模型无法再"看图"），属已知取舍。
- 渲染层：UI 本已支持 `compaction` part 渲染（I1 预留），无需改动。
