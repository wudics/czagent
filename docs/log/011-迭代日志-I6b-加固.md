> 日期：2026-09-02

## 背景

对照 opencode 1.18.19 实现审查 czagent 压缩：发现 1 个正确性问题（二次压缩丢旧摘要）与多项可借鉴机制（prune / 真实 usage 判定 / token 尾部预算 / 摘要剥图）。

## 完成项

- [x] **修二次压缩丢旧摘要**：`maybeCompact` 提取旧 checkpoint 的摘要作为 `previousSummary` 传入 `summarize`，system 提示合并去重 → 新摘要完整包含旧摘要（对齐 opencode 的 previousSummary 机制）
- [x] **prune 工具输出持续清理**（`compaction.ts` `pruneHistory`，请求侧、DB 不动）：从最新往旧扫，跳过最近 2 个 user turn；已完成 tool-result 按 token 从新到旧累计，超过 `PRUNE_PROTECT_TOKENS=40k` 的替换为 `[旧工具输出已清理…]`（tool-call 保留、幂等）。对齐 opencode 的 prune（其 DB 标记式，我们纯请求侧）
- [x] **溢出判定用真实 usage**：`usageTotal`（input+output+reasoning+cache read/write，opencode 口径）取**最近一条带 tokens 的 assistant 消息**（持久化，跨 sendMessage 有效；provider 未回传时为合成值），与字符估算取 max；usage 缺失自然回退估算
- [x] **尾部保留改按 token 预算**：`selectTailStart`（从最新往旧累积 `estimateMessageTokens`，最新一条必留）+ `tailBudget = clamp(usable × preserveRatio, 2k, 15k)`（复用现有配置，语义与 opencode 默认一致）
- [x] **摘要剥图为纯占位（决策 B）**：`summarize` 输入把 image part 映射为文本 `[图片附件: name]`，不再发原图、不依赖摘要模型视觉（opencode serialize 同款）
- [x] **runLoop 重组**：单一估算源（窗口 → prune → 构建请求 → est=max(估算, 持久 usage)）；溢出 → maybeCompact（接收现成窗口，不再内部重算）→ 重建；仍超限 → 丢最旧一条重试 ≤1
- [x] **修复重试 bug**（新测试暴露）：重试原 `slice(start+1)` 会把摘要 checkpoint 一并丢弃 → 改为只丢最旧一条非 checkpoint 消息

## 与 opencode 的对应关系

| 机制 | opencode 1.18.19 | czagent（本次后） |
|---|---|---|
| 溢出判定 | 真实 usage ≥ usable | max(字符估算, 持久 usage) ≥ usable |
| 工具输出 | prune 标记式（40k 保护/20k 起量） | 请求侧占位（40k 保护）+ 3000 字符截断 |
| 尾部保留 | token 预算 min(15k, max(2k, usable×0.25)) | clamp(usable×preserveRatio, 2k, 15k) |
| 摘要输入 | 纯文本 serialize（媒体→占位）+ previousSummary | 剥图占位 + previousSummary |
| 旧数据 | DB 全量（标记/重排） | DB 全量（窗口切片/请求侧替换） |
