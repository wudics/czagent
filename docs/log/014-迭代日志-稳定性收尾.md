## 完成项

### 1. runLoop 早退状态卡死修复（core）
- [x] `config.read()` 失败的早退路径补 settle：置 `idle` + emit `session.status`/`session.updated`（此前直接 return，会话永久卡"运行中"且 abort 已删，停止也救不回）
- [x] 会话不存在的早退无需 settle（行已删除）；走 `appendError` 的路径本就回 idle，不动
- [x] **stopSession 安全网**：既无 abort controller 也不在队列时（任何原因卡在 running/queued）→ 强制回 idle + emit——"停止"按钮永远能解卡

### 2. 窗口饱和强制压缩（core）
- [x] `historyWindow` 返回 `{ messages, saturated }`：`saturated = 窗口内无可见 checkpoint 且 pageMessages(300) 有更多更早消息`（checkpoint 在页内时窗口必然完整）
- [x] runLoop：饱和且 `compaction.auto` 时**绕过 token 预算**强制 `maybeCompact`（usable 传极大值 → 尾部预算钳 15k）；压缩后窗口从 checkpoint 起，通常 ≪300
- [x] `selectTailStart` 增加 **`TAIL_MAX_MESSAGES=200` 条数上限**（token 预算对"大量短消息"无约束力，纯 token 尾部会再次饱和；窗口 300 − 尾部 200 留 100 余量）
- [x] 效果：长会话历史不再被静默丢弃——超窗口部分折叠进摘要（auto=false 用户仍保持原行为，尊重设置）

## UI 小修（验收反馈）

- [x] **侧栏状态文字换行**："运行中"被长 modelId 挤到第二行——根因：flex 里 `truncate` 元素默认 `min-width:auto` 无法收缩。修复：状态文本 span 加 `shrink-0 whitespace-nowrap`（运行中/排队中/待确认），modelId span 加 `min-w-0`（截断真正生效，挤压由 modelId 吸收）；会话头部"排队中"徽标加 `shrink-0`
