## 问题与根因

### 现象
- 长任务运行中两次"无缘无故"停止：一次在 websearch 调用完成后，用户输入"怎么自己停止了？请继续"恢复后继续跑，又一次在 bash 工具调用完成后停止。消息无任何 error 记录，会话直接转 idle。

### 根因（基于 ~/.config/czagent/czagent.db 会话数据 + 代码比对）
- 两次运行 assistant 消息数**均恰好 16 条**（第 16 轮分别以 websearch / bash 工具结果收尾）→ 第 17 轮被掐断，"xx 工具后停止"只是第 16 轮恰好调用的工具，属巧合
- `session-manager.ts` 主循环与子代理循环均写死：`agent?.steps && agent.steps > 0 ? agent.steps : 16` —— steps 未设置时默认 16
- 设置界面承诺"最大步数（**留空=不限**）"（zh-CN/en-US locales），核心代码未兑现，**UI 承诺与实现不一致**
- 主循环步数耗尽 `if (turn > maxSteps) break;` **静默退出**，无任何提示（讽刺的是子代理循环反而有"达到步数上限"提示，主循环没有）→ 表现为"无缘无故停止"

## 完成项

### 1. 留空=不限步数（core）
- [x] 主循环 `runLoop`：steps 未设置/≤0 → `Number.POSITIVE_INFINITY`（显式填数字行为不变）
- [x] 子代理循环 `runSubAgent`：同样改为留空=不限
- [x] 无限循环风险由既有机制兜底：doom-loop 保护（同工具同参连续 3 次 → 询问用户）+ 上下文压缩

### 2. 显式步数耗尽给可见提示（core）
- [x] 主循环新增 `stepsExhausted` 标记：仅当显式设置了步数且跑满时为 true
- [x] 耗尽时向最后一条 assistant 消息 append 可见 text part："已达单次运行最大步数上限……输入'继续'可接着执行"，并 emit + 落库 —— 对齐子代理循环行为，杜绝无声停止
