## 目标

接入 MCP（Model Context Protocol）官方 SDK：本地 stdio 与远程 HTTP 双传输，MCP 工具经适配层进入统一工具注册表，与本地工具同权执行。

## 完成项

### 1. 配置（`core/src/mcp/config.ts`）
- [x] 两层：**全局** `~/.czagent/mcp.json` + **工作区** `<cwd>/.czagent/mcp.json`（工作区覆盖同名 server）；缺失/坏 JSON → 跳过该层不阻塞
- [x] 格式：`{ mcpServers: { <name>: { command, args?, env? } | { url, headers? } } }`；传输判定（显式 type 优先，否则 command→stdio / url→http）

### 2. McpRegistry（`core/src/mcp/registry.ts`）
- [x] **懒连接**：首次列出/调用时连接；Client 缓存复用（避免每轮 spawn）；失败进 30s 冷却期后允许重建；`close()` 统一关闭
- [x] **双传输**：stdio → `StdioClientTransport({command,args,env})`；HTTP → `StreamableHTTPClientTransport` 优先，**失败自动回退 `SSEClientTransport`**（老 server 兼容）
- [x] **工具包装**：`listTools()` → `ToolDef[]`，id = `mcp_<server>_<tool>`（非法字符 sanitize 防冲突）；MCP inputSchema（JSON Schema）与注册表 inputSchema 直接兼容
- [x] **执行**：`callTool(name, args, {signal, timeout 60s})` → content 数组拼接为文本（非文本标注类型）；`isError` → throw（模型可见可自纠）
- [x] **错误隔离**：单 server 连接/列举失败 → 本轮跳过该 server，其它不受影响

### 3. SessionManager 接入
- [x] runLoop 每轮 `await mcp.getTools(cwd)` 并入工具集：build（空 tools）全量包含；显式列表可点名 `mcp_*`；disabled 照常过滤
- [x] system 追加 `<mcp_instructions>`（server+工具清单，仅当有工具）
- [x] **权限（用户决策）**：`mcp_` 前缀工具**直接放行**（resolveForTool 前缀短路）；全部 MCP 默认放行
- [x] 脚本 `ctx.tools` 并入 MCP 工具（`runScriptTool` 支持 def 覆盖，工具卡片同款呈现）；子 agent（build 全量）并入
- [x] `closeMcp()` + main `will-quit` 尽力关闭

### 4. 依赖
- [x] `@modelcontextprotocol/sdk@^1.30.0`（官方，MIT）加入 core dependencies 与 desktop dependencies（desktop 声明使 electron-vite externalizeDeps 外部化，运行时从 node_modules 加载）

## 实施中发现并修复
- **HTTP fixture 无状态模式**：`McpServer` 实例只允许连接一个 transport——stateless 模式必须**每请求新建 McpServer + transport**（官方 stateless 写法），否则第二个请求（notifications/initialized）500
- runLoop 工具执行查 `registry.get` 找不到 MCP 工具 → 增加 `mcpTools.find` 兜底（含 `def` 覆盖参数传递）
- 测试基建：`test/helpers/harness.ts`（共享 fake 协议引擎 harness，支持按调用序返回事件）
