# 022 · I12 — 默认目录改名 czworkspace + 权限删除恢复

日期：2026-09-06
前置：I11（Skill/MCP 配置界面）。

## 目标

1. 默认工作目录由 `用户目录\czagent` 改为 `用户目录\czworkspace`。
2. 权限页删除/恢复语义澄清：规则被删后如何兜底、内置默认规则如何恢复。

## 实现

### A. 默认工作目录 → czworkspace
- `session-manager.ts` createSession：默认 cwd `join(homedir(),'czagent')` → `'czworkspace'`（mkdir recursive 原已有，新建会话自动建目录）。
- `NewSessionDialog` 工作目录输入框占位符改为 i18n（`newSession.cwdPlaceholder`，zh/en：`留空默认 用户目录\czworkspace`）。
- 测试 `session-manager.test.ts` 默认目录断言同步改 `czworkspace`。

### B. 权限删除/恢复
- settings store：新增 `resetRules()`（重置 `permissions.default` 为出厂默认 `createDefaultSettings().permissions.default` 副本并持久化）；导出 `defaultPermissionRules`。
- PermissionsTab：
  - Section 右上角加 **↺ 恢复默认** 按钮（confirm 提示会覆盖自定义规则）。
  - 规则来源标记：与出厂默认（tool+mode 全等）比对 → 标灰色「内置」徽标。
  - 删除：内置规则走专用 confirm（提示删除后的兜底行为 + 可用 ↺ 恢复）；普通规则通用 confirm。
  - hint 说明删除语义与兜底策略：read/grep/glob/webfetch 直接放行；bash/write/edit/patch 询问；其余（含 websearch/skill/mcp_*）一律询问。
- i18n zh/en 同步。

### C. 测试环境隔离（顺带修复——MCP 测试被真实配置污染）
现象：用户通过 I11 界面添加 filesystem server 后，core 测试开始读取真实 `~/.czagent/mcp.json`（serverfs）→ 单测真的 npx 拉起 filesystem server，session-manager 套件跑 54s 且 5 个 mcp 断言失败。
根因：SessionManager/registry 默认 globalDir = `~/.czagent`，runLoop 每次并入 MCP 工具时扫描真实全局层。
修复：
- `mcp/config.ts` 新增 `defaultGlobalDir()`：优先 `process.env.CZAGENT_GLOBAL_MCP_DIR`，否则 `~/.czagent`；三个读/写函数默认参数改用它。
- `session-manager.ts`：3 处 `this.mcp.getTools(cwd)` 透传 `this.opts.globalMcpDir`（脚本 ctx / runSubAgent / runLoop）。
- `vitest.config.ts` 加 `setupFiles: ['test/setup.ts']`，setup 里 mkdtemp 并设 `CZAGENT_GLOBAL_MCP_DIR` → 全部 core 测试隔离真实配置。
- harness：`globalMcpDir` 默认再兜一层（dirX 下临时目录）。
- `mcp.test.ts`：registry/分层读写测试显式注入临时 GLOBAL；设置页数据流测试传独立空 cwd（避免 `mcpGetLayers()` 无 cwd 时把 `~/.czagent/mcp.json` 当作工作区层读入）。
效果：core 套件 54s → 4.9s，无 serverfs 进程，全部通过。
