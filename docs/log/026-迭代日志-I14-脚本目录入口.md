# 026 · I14 — 脚本以工作目录入口直接运行

日期：2026-09-06
前置：想法 5（用户 2026-09-06 提出"脚本以工作目录为单位、约定入口文件、直接运行、无需对话框"）。

## 决策（用户拍板）
1. 入口候选（取先存在者）：`czagent.ts → czagent.js → .czagent/run.ts → .czagent/run.js`。
2. 安全模型 = **与粘贴脚本同沙箱**（esbuild 转 TS + vm；require 仅 node:path/crypto/util；文件/命令等重操作走 ctx.tools + 权限系统），不额外放开 fs。
3. 触发 UI = **会话内切换**（运行入口 / 粘贴代码），▶ 按所选运行。

## 实现

### core
- `provider.ts`：`SendMessageInput` 增 `runEntry?: boolean`（script 会话运行目录入口；text 仅作历史标记）。
- `session-manager.ts`：
  - `findEntryFile(cwd?)`：候选探测（ts→js→.czagent/run.ts→.czagent/run.js），无入口返回 null。
  - `sendMessage`：runEntry 时先探测并校验入口（无入口直接 throw，不落消息/不改状态）；用户消息 text 记为 `▶ 运行入口：<basename>`；脚本分派按 runEntry 走入口执行。
  - `startScriptFileLoop(sessionId, path)`：占槽 → 实时 `readFile` → `runScriptSession`；文件读取失败安全回 idle；完成释放槽位接力队列。

### 桌面
- IPC：`script:entryFile`(cwd) → path|null（preload/main 直通 `findEntryFile`）。
- `chat` store：`send(text, attIds?, opts?: {runEntry})`，runEntry 时允许空文本并透传标记。
- `InputBar`（script 会话）：探测入口后顶部显示「▶ 运行入口 / 粘贴代码」分段 + 右侧入口文件名；入口模式 placeholder 提示内容可不填；▶ 在入口模式允许空内容执行。i18n：`chat.entryRun / pasteCode / entryPlaceholder`。

## 测试（core 196，新增 4）
- `session-entry.test.ts`：
  - findEntryFile 优先级（空→null；仅 .czagent/run.js→该路径；再建 czagent.ts→优先 ts）。
  - 入口端到端：`czagent.ts` ctx.log×2 + 返回值 → user 消息标记「运行入口：czagent.ts」+ 日志/返回值入会话。
  - 无入口 + runEntry → sendMessage reject（含「入口脚本」）；无消息落库、状态保持 idle。
  - 粘贴代码（非 runEntry）回归：仍走源码执行。
