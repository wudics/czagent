## 决策（用户拍板）
- CI 三平台矩阵：要（Linux/mac 不依赖本机）；node-pty 移除 → **实施中撤回**（见下）；图标用户后续提供（先默认图标跑通）；Windows 加 portable。

## 过程与关键发现

### 1. node-pty 移除撤回
最初判断"代码零引用"有误——grep 只扫了 desktop/src，而引用在 **core/src/tools/bash.ts:1**：bash 工具通过 `@lydell/node-pty` 以 PTY 方式 spawn PowerShell/bash（ANSI 剥离即为其存在）。已恢复依赖与 `asarUnpack`，打包时各平台 prebuilt（含 conpty/OpenConsole.exe）正确落位。

### 2. better-sqlite3 rebuild 失败 → N-API 免 rebuild
`@electron/rebuild` 需要 Visual Studio（本机无）→ 失败。排查发现 **better-sqlite3 v13 已改用 N-API prebuilds**（`prebuilds/<平台>.node`，ABI 与 Electron 版本无关）——dev 模式长期正常加载即是证明。配置 **`npmRebuild: false`** 跳过源码 rebuild，dev/打包使用同一二进制，规避 VS 依赖。

### 3. asar 资源布局修复
- `asarUnpack` 增 `@esbuild/**`（脚本子进程 spawn esbuild 二进制必须在 asar 外）；实测产物中 `app.asar.unpacked` 含 @esbuild/@lydell（含 conpty）/sharp/better-sqlite3 及其传递原生依赖（@img/@napi-rs/jszip）。
- 内置技能：`extraResources` → `resources/skills`；main 改为 `app.isPackaged ? process.resourcesPath/skills : __dirname/../../resources/skills`（旧打包路径会落进 asar 且资源未拷入——旧 win-unpacked 已验证该缺陷）。

### 4. CI（`.github/workflows/release.yml`）
push `v*` tag / 手动触发；矩阵 windows/macos/ubuntu；`pnpm install → build → electron-builder --win/--mac/--linux --publish never`；上传 exe/dmg/AppImage/deb。macOS 构建满足"只能在 mac 上打"的平台限制；`CSC_IDENTITY_AUTO_DISCOVERY=false` 跳签名。
