# 039 · 悬空会话模型自动回退 + 接口目录命名精简

日期：2026-09-09
前置：037 重构后用户冒烟反馈三问题——①旧会话的模型下拉显示"（已删除的模型）"（config.json 重置后 sqlite 旧会话 `model_id` 全部悬空所致）；②接口目录显示名 `BigModel（智谱 GLM）`/`Qwen（阿里云百炼）` 后缀冗余；③BigModel glm-5.3-flash 选"不思考"仍输出思考内容。第三项经查证为 API 限制（GLM-5.3 系官方文档明示 thinking 仅能开启、由 reasoning_effort 控强度），用户拍板**搁置不改**。

## 现状结论（调研）

- **悬空显示链**：`InputBar` 在 `session.modelId` 不在启用列表且 `modelById` 查不到时渲染"（已删除的模型）"占位 option；`ModelName`（侧栏/右栏共用）同样兜底显示该文案；设置页绑定区对悬空绑定渲染红色"已删除"徽标。三处均为防御性显示，正常数据路径（settings load 时 `ensureBindingModelId` 校正绑定、删模型时 `rebindAll`）不会触发，但 037 旧配置重置使全部旧会话命中。
- **回退语义缺失**：会话模型解析没有统一规则——UI 显示悬空 id、主循环 `turnTarget` 解析失败才回退，两层各自为政，用户看到"已删除"却不知如何恢复。
- **数据时序**：`main.tsx` 中 `settings.load()` 与 `sessions.init()` 并行无顺序保证，任何"打开会话即修复"逻辑必须以 `settings.loaded` 为守卫，否则可能把有效模型误判为悬空。

## 决策（用户拍板）

- **统一解析回退链，彻底移除"已删除的模型"字样**：会话自身 modelId（有效时）→ chat 能力绑定 → 第一个启用对话模型 → 都没有显示「未配置」。
- 打开会话时悬空 modelId 按回退链 **patch 持久化**（未配置任何模型时不动，仅显示层提示）。
- 目录显示名去掉中文后缀：`BigModel` / `Qwen`。

## 变更

- **解析回退链**（`desktop/renderer/stores/settings.ts`）：新增 `resolveChatModelId(sessionModelId?)`——①会话 id 在启用对话模型中 → 原值；②chat 绑定有效 → 绑定值；③第一个启用对话模型；④`''`（未配置）。
- **会话打开修复**（`stores/chat.ts` `open()`）：`settings.loaded` 守卫下，`meta.modelId` 非空且解析结果非空且 ≠ 原 id → `useSessionsStore.patch` 落库 + 同步 meta（InputBar/侧栏立即恢复，重启保持，主循环直接解析成功）；未配置模型不 patch。
- **InputBar**：删除悬空占位 option；Select value 改用解析结果；解析为空（无任何模型）显示 disabled「未配置」option（复用既有 `settings.models.unbound` 文案）；`modelById` 引用清理。
- **ModelName**（侧栏会话列表 + 右栏共用）：按 `resolveChatModelId` 解析后显示模型名，空 → 「未配置」，不再有"（已删除的模型）"。
- **ModelsTab 绑定区**：删除悬空绑定红色徽标；Select value 悬空回落「未配置」项。
- **locales**：删除死键 `settings.models.modelDeleted`（zh/en）。
- **catalog**：显示名 `BigModel（智谱 GLM）` → `BigModel`、`Qwen（阿里云百炼）` → `Qwen`（设置页下拉与模型徽标自动生效）。
- **文档**：`docs/dev/ui-design.md` 模型下拉与 settingsStore 条目更新（回退链、占位移除、派生方法使用约束）。
