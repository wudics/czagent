# 043 · 会话列表模型名启动时误显示「未配置」

日期：2026-09-10
前置：042 合入后用户反馈的 UI 时序问题。

## 问题（用户反馈）

刚打开程序时，左侧会话列表每个会话项的模型名称显示「未配置」；只有点击「新建会话」或点击某个会话后，模型名称才显示出来。

## 根因

`ModelName.tsx` 的 zustand selector 订阅的是**函数引用**（`s.resolveChatModelId` / `s.modelById`），这两个引用在 store 创建时就固定不变：

1. `main.tsx` 中 `sessions.init()` 与 `settings.load()` 并行发出且不等待，立即渲染首帧；
2. 首帧时 settings 仍为空默认值（`chatModels: []`）→ `resolveChatModelId()` 返回 `''` → 显示 `t('settings.models.unbound')` =「未配置」；
3. `load()` 完成后 `set({ settings, loaded: true })`，但 selector 输出（函数引用）未变 → zustand 判定无变化，**不触发 ModelName 重渲染**；
4. 点击会话（`activeId` 变化）或新建会话（`sessions` 数组换引用）才连带重渲染，此时才读到已加载的 settings，模型名"突然"出现。

数据层无问题：DB 中 `model_id` 一直存在（`core/.../session-manager.ts` `listSessions()` 原样返回），纯渲染进程订阅缺陷。若点击当前已激活会话（引用均不变），模型名应仍停留「未配置」——可作根因验证实验。

## 变更

- **`desktop/.../components/layout/ModelName.tsx`**：selector 从订阅函数引用改为订阅 `s.settings` 本身（load 完成后引用变化即触发重渲染，与 `InputBar.tsx` / `NewSessionDialog.tsx` 既有正确范式一致）；`useMemo` 派生启用模型列表，内联原 `resolveChatModelId` 回退链（会话 id → chat 绑定 → 第一个启用模型，含"绑定模型须已启用"校验），显示名查找保留 chatModels → multimodalModels 双表回退（对齐原 `modelById` 语义）。组件签名与 i18n key 不变。
