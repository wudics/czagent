# 049 · 迭代日志 — MCP 生效名单与工具加载解耦（修复 MCP 静默清零）

> 日期：2026-10-08
> 状态：✅ 完成（typecheck / 测试 119 / build / 真机端点抽查通过）
> 关联：`023`（I13 MCP 三态）、`024`（I13.1 工具矩阵）、`018`（I9 MCP 客户端）

## 问题现象

用户配置 2 个远程 MCP（weknora 知识库 / amap 高德），设置页「测试连接」weknora 正常列出工具，amap 报 503；对话中让 AI 查知识库、规划路线，均未唤起任何 `mcp_*` 工具。全库历史 `mcp_*` 工具调用数为 0。

## 根因

### 1. 默认 build/plan agent 实际拿不到任何 MCP 工具（本轮修复主体）

I13 的 MCP 三态语义依赖 `isAgentAllOpen()` 区分「全开 agent / 受限 agent」：

- 全开 agent → 并入「全局 `enabled` 且 agent 未 `off`」
- 受限 agent → **只**并入 `agent.mcp[name] === 'on'` 的服务器

但这把「全开/受限」的判据绑在了工具加载链上：I13.1 用 `toolOverrides` 取代能力组后，`isAgentAllOpen()` 变成「`toolOverrides` 中不存在任何 `load: boolean`」，而 `materializeAgentMatrix`（工具矩阵**首次编辑**即调用）会把全部工具物化成 `{ load: true }` —— 于是用户在矩阵里点任意一行，build 就从「全开」永久翻成「受限」，MCP 静默清零。出厂 `plan` agent 带 `tools: [...]` 白名单，天然「受限」，从来就没有 MCP。

按用户真实 `config.json` 实算：

| agent | isAgentAllOpen | 修复前生效名单 | 修复后 |
|---|---|---|---|
| build | false | `[]` | `['weknora']` |
| plan | false | `[]` | `['weknora']` |
| 猛男村妹子 | false | `[]` | `['weknora']` |
| 猛男村村长 | false | `['amap','weknora']` | 不变 |

> 旁证：最新会话 `s-muz38any-22` 中，模型 reasoning 原文「available tools are for reading/writing files, searching knowledge bases, **not for map services**」——它确实看到了 weknora 工具（该 agent 显式 `weknora: on`），只是 amap 被静默丢弃，随后回答「我目前没有可用的工具来调用高德地图」。

### 2. amap 503 = 服务端并发池耗尽（**本轮未修**，非配置错误）

直连该端点（POST `initialize`，间隔 9s 重试 3 次）均返回：

```
HTTP/2 503
{"jsonrpc":"2.0","error":{"code":-32000,
 "message":"模块 amap-maps 并发会话已达上限 16，等待 8000ms 后仍无空位",
 "data":{"retryable":true,"module":"amap-maps","max":16}}}
```

属 vendor 端会话池占满，客户端无法绕过。两处客户端问题留待后续迭代：① `connectHttpWithFallback` 丢弃 streamable 原始错误、只上报 SSE 的 `Non-200 status code (503)`，真实原因不可见；② SDK 的 `StreamableHTTPClientTransport.close()` 不发 DELETE，从未调用 `terminateSession()`，测试连接 / 30s 冷却重连 / 应用重启都在服务端留下不回收的 session，加剧占槽。

## 本轮实现（仅「① 生效名单解耦」，范围最小）

### core

- **`mcp/config.ts`**：新增导出纯函数 `resolveMcpServerNames(config, agentMcp?)` —— 默认并入 `enabled !== false`，agent `'off'` 排除、`'on'` 顶回全局关；判定不再涉及任何工具加载信息（放在纯模块以便直接单测，对齐 `tools/policy.ts` 风格）。
- **`node/session-manager.ts`**：
  - `allowedMcpServers()` 改为委托 `resolveMcpServerNames(config, ag?.mcp)`，去掉 `isAgentAllOpen` 分叉；
  - 删除 `isAgentAllOpen()`（改后已无引用）；`runSubAgent` 的 MCP 并入条件由 `!agentOpts?.tools && isAgentAllOpen(agentDef)` 简化为 `!agentOpts?.tools` —— 保留「显式 `tools` 白名单仍可过滤 MCP 工具」的既有语义，只是不再被工具加载链牵连；
  - import 调整：`isMcpServerEnabled` → `resolveMcpServerNames`。

主循环（`mcpToolsFor`）、上下文估算（:904）、脚本路径（`scriptMcpAllowed`）、子代理四条链路共用同一个 `allowedMcpServers`，自动同步，无需单独改动。

### desktop

- `settings.agents.mcp.hint`（zh/en）改写：原文案「全开 agent 默认并入全部启用服务器；受限 agent 需点「开」才并入」在改动后已是错的，改为「默认「跟随全局」启停（全局启用即并入）；「排除」= 该 Agent 不带此服务器；「强制开」= 顶回全局已关闭的服务器。工具矩阵不影响 MCP」。

### 测试（新增 `core/test/mcp.test.ts`，13 个）

改前 `packages/core/test/` 下**零** MCP 测试（历史 184 用例中的 mcp 组已不在仓库）。新增覆盖：

- **049 回归点**：`toolOverrides` 物化（`load: boolean`）的 agent 仍并入全局启用服务器；
- `'off'` 排除、`'on'` 顶回全局 `enabled:false`、未点名的全局关闭服务器不带入、`undefined` 跟随全局、空配置；
- `plan` agent（遗留 `tools` 白名单 + `toolOverrides`）同样并入；
- 配置层回归：`isMcpServerEnabled` / `serverTransport` / `mcpServerPrefix` / 两层 `mcp.json` 合并（工作区覆盖同名）+ 坏 JSON 跳过。

## 边界与后续

- **amap 仍不可用**：服务端 16 槽占满，与本轮改动无关；且 MCP 连接失败仍是**静默**的（`McpRegistry.ensure` 吞掉错误），模型据此可能继续说「没有可用工具」。要让它在 build 生效还需把 build 的 `mcp.amap` 从 `off` 改回「跟随全局」，但服务端不恢复前依然连不上。
- 待办（本轮明确不做，用户已确认）：① `terminateSession()` 会话回收，防自己撑爆 vendor 池；② `retryable`/503 退避重试；③ 可观测性 —— registry 暴露 `getStatus()`、设置页每行显示运行期状态、会话内插 `error` part、`<mcp_instructions>` 旁加 `<mcp_unavailable>` 段；④ `callTool` 会话失效重连。
- **权限不变**：MCP 工具仍默认 `ask`（`defaultToolPolicy` 未知工具兜底），每次调用弹确认；想免打扰可在 设置 → 权限 → 补充规则 加 `mcp_*` = allow。
- 兼容性：存量 agent 上残留的 `mcp: { amap: 'off' }` 语义不变（显式排除照旧生效），用户配置文件无需迁移。
