# 050 · 迭代日志 — 模型额外请求参数与思考档位覆盖

> 日期：2026-10-26
> 状态：✅ 完成（typecheck / core 测试 122 / AMD 端点实测）
> 关联：`docs/dev/llm-engine.md §4.4`、`docs/dev/data-model.md §2.4`、`docs/dev/ui-design.md`（模型设置）

## 需求

1. AMD Radeon Cloud 等 OpenAI 兼容平台需要通过请求体参数控制思考（如 `reasoning_effort`），不能只依赖内置引擎映射。
2. 设置页「添加/编辑模型」只保留**一个**高级参数输入框，不把 off/on/deep 拆成多个输入。
3. 所有 chat 模型都可配置额外参数；新模型默认折叠，已有配置的模型默认展开。
4. 同一份 JSON 既要能表达每次请求都带的静态参数，也要能表达按会话思考档位覆盖的参数，同时不影响 `temperature` 等静态参数。
5. 弹窗内容超高时必须内部滚动，不能溢出视口。

## 实现

### core

- **`provider.ts`**：`ChatModelConfig` 新增 `thinkingOptions?: Partial<Record<ThinkingMode, Record<string, unknown>>>`；`MultimodalModelConfig` 同步支持（图片理解等走 chat 协议的能力可用）。
- **`llm/types.ts`**：`ChatBinding` 增加 `options` / `thinkingOptions`，网关解析后随绑定一起传给引擎。
- **`llm/gateway.ts`**：`resolveChat` 把模型级 `options`/`thinkingOptions` 写入 `binding`；`Gateway.chat` 将模型 `options` 与请求级 `options` 合并，调用方优先。
- **`llm/engines/openai-stream.ts`**：
  - 请求体合并优先级：引擎内置 `thinkingParams(mode)` → 模型 `options` → 请求级 `options` → 模型 `thinkingOptions[mode]`。
  - 过滤协议关键字段 `model` / `messages` / `stream` / `stream_options`，额外参数不能覆盖。
  - 未指定 `reasoningField` 时自动识别流式 delta：先 `reasoning_content`，再 `reasoning`（兼容 AMD 等平台），不再需要按模型配置字段名。

### desktop

- **`settings/ModelsTab.tsx`**：
  - 高级参数改为单个 JSON 文本框；外层键存 `options`，保留键 `thinkingModes` 存 `thinkingOptions`。
  - `thinkingModes` 仅允许 `off` / `on` / `deep`，每个值必须是对象；非法 JSON / 非对象 / 非法档位键在保存前报错，不写入配置。
  - 新模型默认折叠；已有 `options` 或 `thinkingOptions` 的模型默认展开。
  - 编辑回显时把 `options` 与 `thinkingOptions` 重新合并成同一份 JSON。
  - 弹窗壳改为 `max-h-[85vh]` + 固定标题栏 + 内容区 `overflow-y-auto`，修复内容溢出视口。
- **`settings/fields.tsx`**：补充 `TextArea` 组件。
- **`locales/zh-CN.ts` / `en-US.ts`**：新增高级参数、校验错误与折叠提示文案。

### 文档

- `docs/dev/llm-engine.md`：新增 §4.4「模型额外请求参数（高级参数）」，更新引擎差异表与 options 合并说明。
- `docs/dev/data-model.md`：`ChatModelConfig` / `MultimodalModelConfig` 补充 `thinkingOptions`，说明单 JSON 的存储拆分。
- `docs/dev/ui-design.md`：模型设置区补充高级参数说明。

## 使用方式

单框 JSON 示例：

```json
{
  "temperature": 0.7,
  "thinkingModes": {
    "off": { "reasoning_effort": "none" },
    "on": { "reasoning_effort": "medium" },
    "deep": { "reasoning_effort": "xhigh" }
  }
}
```

- 外层键：每次请求都合并。
- `thinkingModes`：仅会话选中对应档位时合并该桶；未配置的档位只发外层静态参数。
- `temperature` 等静态参数不随思考档位变化。

## AMD Radeon Cloud 实测

### Qwen3.8-Flash-Next

- `reasoning_effort: medium/xhigh` 正常返回 reasoning。
- `reasoning_effort: none` **被接口忽略**，仍返回 reasoning（实测 319 字符 / 116 reasoning tokens）。
- 真正关闭思考需要 `chat_template_kwargs.enable_thinking = false`，实测 reasoning 长度为 0：

```json
{
  "thinkingModes": {
    "off": { "chat_template_kwargs": { "enable_thinking": false } },
    "on": { "reasoning_effort": "medium" },
    "deep": { "reasoning_effort": "xhigh" }
  }
}
```

> `off` 桶不要再同时写 `reasoning_effort: "none"`，避免两个参数冲突。

### DeepSeek-V4-Flash

- 直接请求 AMD 端点，`none` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max` 均返回 `reasoning_tokens = 0`，不产生思考内容。
- 属于 AMD 当前接口/模型侧限制，不是 czagent 配置问题；需要思考可改用 Qwen3.8-Flash-Next，或等待 DeepSeek-V4.1-Flash 并发限制缓解后验证。

## 边界

- 额外参数只对走 `openai-stream.ts` 的 chat 引擎生效；OpenAI 兼容兜底与内置引擎共用同一合并逻辑。
- 协议关键字段始终以代码生成为准，额外参数中的同名键会被忽略。
- 平台对参数的实际支持程度由服务端决定；文档无法覆盖的厂商差异，通过模型级 JSON 配置处理。
