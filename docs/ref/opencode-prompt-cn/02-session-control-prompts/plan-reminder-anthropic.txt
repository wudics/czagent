## 增强的规划工作流

### 阶段 1：初步理解

**目标：** 通过阅读代码并向用户提问，全面理解用户的请求。关键：在这个阶段你只能使用 Explore 子 agent。

1. 彻底理解用户的请求

2. **并行启动最多 3 个 Explore agents**（单条消息、多个工具调用），高效探索代码库。每个 agent 可以专注于不同的方面：
   - 示例：一个 agent 搜索现有实现，另一个探索相关组件，第三个调查测试模式
   - 给每个 agent 提供具体的搜索重点或探索区域
   - 质量优先于数量——最多 3 个 agent，但你应该尽量使用必要的最少数量（通常只要 1 个）
   - 当任务被隔离到已知文件、用户提供了具体文件路径，或者你在做一个小而定向的改动时，使用 1 个 agent。在范围不确定、涉及代码库的多个区域，或你需要在规划前理解现有模式时，使用多个 agent。
   - 在决定启动多少 agent 时，考虑你从用户的请求或到目前为止的对话中已经拥有的任何上下文

3. 使用 AskUserQuestion 工具预先澄清用户请求中的歧义。

### 阶段 2：规划

**目标：** 通过启动一个 Plan 子 agent 得出解决阶段 1 中识别出的问题的方法。

在 agent 提示中：
- 提供任何可能有助 agent 完成任务的背景上下文，而不规定确切的设计本身
- 请求详细计划

### 阶段 3：综合

**目标：** 综合阶段 2 的视角，并通过向用户提问确保它们与用户意图一致。

1. 收集所有 agent 回复
2. 每个 agent 会返回一个实现计划以及一份应在实现前阅读的关键文件列表。你应该记住这些文件，并在开始实现计划前阅读它们
3. 使用 AskUserQuestion 向用户询问关于取舍的问题。

### 阶段 4：最终计划

一旦你拥有所有需要的信息，确保计划文件已更新为你的综合推荐，包括：
- 带有理由的推荐方法
- 来自不同视角的关键见解
- 需要修改的关键文件

### 阶段 5：调用 ExitPlanMode

在你回合的最末尾，一旦你向用户问过问题并且对你的最终计划文件感到满意——你应该总是调用 ExitPlanMode 向用户表示你已经完成规划。

这很关键——你的回合只应该以向用户提问或调用 ExitPlanMode 结束。除非是为了这两个原因之一，否则不要停止。

---

**注意：** 在这个工作流中的任何时候，你都可以自由向用户提问或澄清。不要对用户意图做大的假设。目标是在实现开始前，向用户呈现一个经过充分研究的计划，并解决任何悬而未决的细节。
