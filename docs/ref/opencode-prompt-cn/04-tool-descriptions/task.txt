启动一个新 agent，让它自主处理复杂、多步骤的任务。

使用 Task 工具时，你必须指定一个 subagent_type 参数来选择合适的 agent 类型。

何时不要使用 Task 工具：
- 如果你想读取某个具体的文件路径，使用 Read 或 Glob 工具而不是 Task 工具，这样能更快找到匹配项
- 如果你想搜索特定的类定义（如 "class Foo"），使用 Grep 工具而不是 Task 工具，这样能更快找到匹配项
- 如果正在搜索特定文件或 2-3 个文件中的代码，直接使用 Read 工具而不是 Task 工具，这样能更快找到匹配项
- 如果没有合适的 agent 可用，直接使用其他工具

用法说明：
1. 尽可能并发启动多个 agent，以最大化性能；为此，在一条消息中使用多个工具调用
2. 委派任务给 agent 后，不要自己重复做同样的工作。继续做不重叠的任务，或等待结果。对于后台任务，结果就绪时会自动通知你。
3. agent 完成后，它会给你返回一条消息。该结果对用户不可见。要向用户展示结果，你应该向用户发送一条文本消息，简洁总结结果。输出包含一个 task_id，你以后可以复用来继续同一个 subagent 会话。
4. 每个 agent 调用都从一个全新上下文开始，除非你提供 task_id 恢复同一个 subagent 会话（它会继续之前的消息和工具输出）。重新开始时，你的提示词应包含高度详细的任务描述，让 agent 自主执行，并且你应该确切指定你希望它在最终消息中返回什么信息。
5. agent 的输出一般应该被信任
6. 明确告诉 agent 你希望它编写代码还是只做研究（搜索、文件读取、web 抓取等），因为它不知道用户的意图。如果可能，告诉它如何验证工作（例如相关的测试命令）。
7. 如果 agent 描述提到它应该被主动使用，那么你应该在用户要求之前尽力使用它。运用你的判断。
