为当前编码会话创建并维护一个结构化的任务列表。跟踪进度、组织多步骤工作，并向用户展示状态。

## 何时使用
在以下情况主动使用：
- 任务需要 3+ 个不同步骤或操作（不只是 3 次工具调用用于单个概念步骤）
- 工作不平凡，受益于规划
- 用户提供多个任务（编号或逗号分隔），或明确要求一个 todo 列表
- 新指令到达——把它们捕获为 todos
- 你开始一个任务——把它标记为 `in_progress`（一次只有一个）
- 你完成一个任务——把它标记为 `completed`，并添加工作中发现的任何后续事项

## 何时不要使用
在以下情况跳过：
- 工作是一个单一的、直接的任务（或少于 3 个琐碎步骤）
- 请求纯粹是信息性的或对话式的
- 跟踪不增加组织价值

## 状态
- `pending` - 未开始
- `in_progress` - 主动工作中（任意时刻恰好一个）
- `completed` - 成功完成
- `cancelled` - 不再需要

## 规则
- 实时更新状态；不要批量完成
- 只有在必需的工作实际完成（包括任何必需的验证）后才标记为 `completed`。绝不基于意图。
- 只要有工作剩余，就恰好保留一个 `in_progress`
- 如果受阻或部分完成，保持 `in_progress` 并添加一个描述阻塞器的后续 todo
- 原样保留用户提供的命令（flags、args、顺序）
- 条目应具体且可操作；把大工作拆分成更小的步骤

## 示例

使用它：
- "添加暗色模式切换并运行测试" -> 多步骤功能 + 明确验证
- "把 getCwd 重命名为 getCurrentWorkingDirectory" -> grep 显示 15 个仓库中的出现位置，涉及 8 个文件
- "实现注册、目录、购物车、结账" -> 多个复杂功能

跳过它：
- "如何打印 Hello World" -> 信息性
- "给 calculateTotal 添加注释" -> 单次编辑
- "运行 npm install 然后告诉我发生了什么" -> 一个命令

拿不准时，使用它。
