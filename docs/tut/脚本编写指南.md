# czagent 脚本编写指南

> 适用版本：I14.1（node 子进程 + 工作目录入口）。迭代脉络见文末「16. 版本与相关文档」。
> 面向读者：需要在 czagent 中用代码编排任务的用户。
> 运行环境：真实 **node 子进程**（esbuild bundle 打包 TS 与依赖），Windows / macOS / Linux 通用。

---

## 1. 这是什么

**脚本会话**是 czagent 的一种会话模式：**以工作目录为单位**，把编排逻辑写进入口文件（`czagent.ts`），点 ▶ 即运行。脚本可以：

- **直接调用全部内置工具**（读写文件、执行命令、联网搜索、图像/视频/语音生成……），每一次调用都以工具卡片的形式实时出现在会话消息流里；
- **委派子 agent**（`ctx.agent.run`）完成需要"智能判断"的子任务；
- 用 `ctx.log` 输出进度，用返回值汇总结果。

与对话会话的区别：

| | 对话（chat）会话 | 脚本（script）会话 |
|---|---|---|
| 运行内容 | 输入框文字交给模型 | 工作目录**入口文件**的代码 |
| 输入框 | 正常输入 | **无输入框**，只有「▶ 运行」条 |
| 决策者 | 模型自主决定调用什么工具 | **你**在代码里显式编排每一步 |
| 适用场景 | 探索式问答、模糊任务 | 批量处理、固定流水线、并行子任务、可复用工具链 |
| 模型的参与 | 全程 | 仅被你 `ctx.agent.run` 调度的时刻 |

典型用法：代码审查流水线、批量转写音频、定期生成报表 + 图表（图像工具）、多方案并行调研。

## 2. 快速入门（30 秒）

1. 在工作目录（新建脚本会话时可指定；默认 `用户目录\czworkspace`）创建 `czagent.ts`：

```ts
export default async function main(ctx) {
  ctx.log('你好，czagent 脚本！');
  ctx.log('工作目录：', ctx.session.cwd);
  return { ok: true, cwd: ctx.session.cwd };
}
```

2. 新建会话 → 模式选「**脚本**」→ 工作目录填上一步所在目录。
3. 点击底部「**▶ 运行**」。脚本会话没有输入框——要改逻辑，直接编辑 `czagent.ts` 再点 ▶（每次运行都重新读盘）。
4. 消息流出现运行记录：用户消息标记 `▶ 运行入口：czagent.ts`，日志逐行滚动，最后追加 `✅ 脚本执行完成` 与返回值 JSON。

## 3. 入口文件与运行模型

### 3.1 入口约定

按顺序取**第一个存在者**（相对会话工作目录）：

```
czagent.ts  →  czagent.js  →  .czagent/run.ts  →  .czagent/run.js
```

必须导出一个 default 函数（建议 async），运行时 `ctx` 是唯一入参：

```ts
export default async function main(ctx) {
  // 你的编排逻辑
  return 结果; // 以 JSON 写入消息流
}
```

- 没有入口文件：点 ▶ 时直接报错「未找到工作目录入口脚本」，不产生消息。
- 没有 default 导出 / 导出不是函数：报错「脚本必须导出 default 函数」。
- 完整 TypeScript（类型标注、interface、泛型、`import`）；由 esbuild 转译打包，运行的是真实 Node。

### 3.2 一次"运行"的完整生命周期

```
点 ▶ ──► 探入口 ──► esbuild bundle（TS+依赖 → CJS 临时文件）
                 ──► spawn node 子进程（stdio 桥注入 ctx）
                 ──► main(ctx) ──► 日志/工具卡片实时流回会话
                 ──► resolve → 「✅ 脚本执行完成 + 返回值」 / reject → 红色 error 卡片
                 ──► 清理临时文件，会话回 idle
```

- **每次运行都重新读盘 + 重新打包**：改完代码即生效，无需任何"重载"。
- 脚本运行**占用一个并发槽**（设置 → 通用 → 最大并发会话数，默认 4）；槽满时进入「排队中」，有空槽自动接力（接力时重探入口文件）。
- 同一会话运行/排队期间再次点 ▶ 会被拒绝（防重入）。
- **应用退出时子进程一并终止**；下次启动会把残留的"运行中/排队中"状态自动复位为空闲。

### 3.3 历史与复用

每次运行都是一个独立的 assistant 消息（日志 + 工具卡片 + 结果/错误），历史全部保留在消息流，可对比不同次的输出。入口文件本身用 git/编辑器管理——脚本不再是"贴在聊天里的一次性代码"。

## 4. 运行环境

| 项 | 值 |
|---|---|
| 执行位置 | 独立 **node 子进程**，工作目录 = 会话 `cwd` |
| 信任模型 | **不做沙箱限制**（等同 `npm run` 你自己的项目脚本）：`fs`、网络、`child_process` 都可用 |
| 模块 | 完整 Node：`import` / `require`、**npm 第三方包（含 ESM-only）经 bundle 可用** |
| 超时 | **默认不限**。设置 → 通用 → 「脚本超时（分钟）」可设上限（0 = 不限）；到期即报 `脚本执行超时（Ns）`，并给子进程 5 秒宽限后强制终止 |
| 停止（■） | `ctx.signal` 立即 aborted；脚本 **5 秒宽限**内优雅退出则正常结束，超宽限**强杀进程** |
| `console` | `log/info` 原样、`warn/error` 加前缀，全部转为 `ctx.log` 进入消息流 |
| 已知限制 | ① stdout 被协议占用：`process.stdout.write` 的内容会**降级为日志行**显示；② `ctx` 相关调用参数与返回值必须**可 JSON 序列化**（跨进程传递）；③ native 插件（.node）不被 bundle，依赖运行时 require，失败时错误信息透传 stderr |

> 建议：文件与网络操作优先走 `ctx.tools`（见 §6）——不仅为了权限确认，更因为每次调用会生成消息流卡片，运行过程可见、可审计、可在出错时定位到具体一步。
>
> 内置库与第三方包的实盘用法见示例 **§12.7（node:fs/path/crypto）** 与 **§12.8（zod/dayjs）**。

## 5. `ctx` API 总览

| 成员 | 类型 | 说明 |
|---|---|---|
| `ctx.session` | `{ id, cwd, model, mode }` | 会话信息；`cwd` 即工作目录（相对路径基准） |
| `ctx.settings` | `{ general }`（只读快照） | 「通用」设置项的只读副本（I18）：如 `general.websearch.maxResults`、`general.compaction.*`、`general.scriptTimeoutMinutes`；**不含 API Key**（Provider 配置不暴露），且整体冻结不可改 |
| `ctx.tools.<id>(input, opts?)` | `(input, { timeoutMs? }) => Promise<结果>` | 调用内置工具与 MCP 工具（过权限系统，卡片进消息流）；id 见 §6；`timeoutMs` 为该次调用限时（I18） |
| `ctx.agent.run(prompt, opts?)` | `(string, opts?) => Promise<string>` | 委派一个隔离子 agent 自主完成任务，返回其最终文本，见 §7 |
| `ctx.log(...args)` | | 向消息流写一行日志（对象自动 JSON 化） |
| `ctx.ask({ tool, args })` | `=> Promise<'allow'\|'deny'\|'allowAlways'>` | 主动弹权限卡征询用户，见 §8 |
| `ctx.signal` | `AbortSignal` | 停止/超时中止感知，见 §9 |

> `question` 与 `task` 两个工具**不能**在脚本中调用（面向主会话模型）；脚本中派生子任务用 `ctx.agent.run`。
>
> `ctx.settings` 典型用法：按配置分支而不用硬编码，例如 `if ((ctx.settings.general.websearch.maxResults ?? 8) > 5) { … }`。

`ctx.settings.general` 完整字段（`GeneralSettings` 快照，均为只读）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `language` | `'zh-CN' \| 'en-US'` | 界面语言 |
| `theme` | `'light' \| 'dark' \| 'system'` | 主题 |
| `maxConcurrency` | number | 最大并发会话数 |
| `titleAutoRounds` | number | 标题自动生成轮数（0=关闭） |
| `websearch.engines` | string[] | 启用的搜索引擎（按固定优先级过滤） |
| `websearch.maxResults` | number | 搜索结果条数 |
| `compaction.auto` | boolean | 自动压缩开关 |
| `compaction.reservedTokens` | number | 压缩保留预算（tokens） |
| `compaction.preserveRatio` | number | 压缩保留窗口比例 |
| `disabledSkills` | string[] | 全局禁用的技能名列表 |
| `scriptTimeoutMinutes` | number | 脚本单次运行超时（分钟；0=不限） |
| `chatInitialMessages` | number | 打开会话初始加载的历史消息条数 |
| `chatPageMessages` | number | 向上滚动加载历史时每页条数 |

## 6. `ctx.tools` —— 调用工具

### 6.1 通用规则

- 与模型使用完全同一套工具、同一套**权限系统**：写 cwd 外文件、危险 bash 等会弹权限卡，允许后继续。
- 每次调用生成消息流卡片（运行中 → 完成/失败），返回值同时交给脚本变量。
- **单次调用限时**（I18）：`await ctx.tools['video-generate']({ prompt }, { timeoutMs: 120_000 })` —— 该次调用超过限时即 reject（`工具调用超时（Ns）：xxx`），不会拖死整个脚本；缺省不限（脚本整体超时仍生效）。
- 图像/视频/语音类工具是**富输出**：图片、文件会作为独立 part 直接显示在会话里；脚本拿到的是文字描述（含落盘路径）。
- 权限拒绝时 Promise **reject**（错误信息 `用户拒绝了 xxx 操作`），需要兜底请 try/catch。
- 与主会话不同：`ctx.tools` **不受工具矩阵"加载"开关限制**（矩阵控制的是模型上下文里给模型看什么；脚本里是你显式调用的代码）。矩阵的**权限**列仍然生效（deny 直接拒绝、ask 弹卡）。仅 `plan/plan-exit/question/task` 四类对脚本不可用。
- MCP 工具同样挂在这里，id 形如 `mcp_<server>_<tool>`（服务器是否并入取决于会话 Agent 的服务器三态/全局启用；调用免权限确认）。

### 6.2 内置工具速查

| 工具 | 入参 | 行为要点 |
|---|---|---|
| `read` | `file`，`offset?`，`limit?` | 带行号读取；默认 2000 行；大文件分段 |
| `grep` | `pattern`，`path?`，`include?` | 正则（大小写不敏感）+ 文件 glob 过滤 |
| `glob` | `pattern`，`path?` | 文件名匹配（`src/**/*.ts`），返回路径列表（换行分隔，结果条数有上限） |
| `write` | `file`，`content` | 创建/覆盖；cwd 内直接写，**cwd 外弹权限卡** |
| `edit` | `file`，`oldText`，`newText` | 精确替换（oldText 须唯一） |
| `patch` | `patch`（apply_patch 格式补丁文本） | 一次改多文件；cwd 外目标弹卡 |
| `bash` | `command` | Windows 走 **PowerShell**（`-NoProfile -NonInteractive`），类 Unix 走 bash；超时 60s；输出超长截断；危险命令（`rm -rf /`、`curl … | sh` 等）强制弹卡 |
| `webfetch` | `url` | HTML → 纯文本（自动按 charset 解码）；原始响应上限 2MB；正文 >2000 字符自动落盘，返回「预览 + 已存至 <路径>，可用 read 分段读取」 |
| `websearch` | `query` | 国内引擎固定优先级（必应→百度→360→搜狗），结果条数取设置；每引擎抓取间隔 2s 防反爬 |
| `skill` | `name` | 加载 `<available_skills>` 中的技能正文（被全局禁用的技能会拒绝） |
| `embed` | `text` 或 `texts[]` | 语义向量（模型/Provider 由能力绑定） |
| `rerank` | `query`，`documents[]`，`topN?` | 相关性重排 |
| `image-generate` | `prompt`，`size?`，`ratio?` | 文生图；Agnes 用档位 `1K/2K…`+`ratio`，OpenAI 兼容系用 `1024x1024` 式精确尺寸；结果图片直接进消息流 |
| `image-edit` | `prompt`，`image[]`（URL/本地路径），`size?`（agnes 档位 1K/2K/3K/4K，默认 1K），`ratio?`（agnes，默认 1:1） | 图生图/多图合成；当前仅 Agnes 图像模型支持 |
| `video-generate` | `prompt`，`seconds?`，`aspectRatio?` | 文生视频；轮询可长达数分钟（工具卡片实时显示进度%）；产物 mp4 落盘并返回路径 |
| `video-from-frame` | `prompt`，`firstFrame`（公开 URL），`lastFrame?`（仅 agnes），`seconds?`（"4"–"12"，仅 agnes，默认 "5"），`aspectRatio?`（16:9/9:16/1:1，默认 16:9） | 图生视频；Agnes 要求素材为公开可访问 URL，OpenAI 兼容系可传本地路径（自动转 data URI） |
| `tts` | `text`，`voice?` | 文字转语音，产出 mp3 路径；音色 8 预置（alex/benjamin/charles/david/anna/bella/claire/diana），简写自动补 `<模型>:` 前缀 |
| `asr` | `file`（本地音频路径） | 语音识别 → 文本 |
| `todo` | `todos?`（全量清单）或 `statuses?`（`{"1":"completed"}`，1 基下标） | 维护右侧「任务清单」面板——脚本同样适用（见 §13.4） |

（调用名即表中"工具"列：`await ctx.tools.read({ file: 'src/app.ts' })`。）

## 7. `ctx.agent.run` —— 委派子 agent

```ts
const summary = await ctx.agent.run('阅读 docs/ 下所有 md，输出三行以内的要点清单。');
```

### 7.1 行为

- **隔离上下文**：子 agent 只看到自己的 system prompt + 你给的 prompt + 环境块，**看不到**当前会话历史；需要背景请写进 prompt，或让它自己读文件。
- 自主多轮：每轮可调用工具（按目标 agent 的工具矩阵生效，或你显式传入的白名单），过程以工具卡片 + `[agent]` 前缀文本实时流入主会话消息。
- 默认 agent 为 `build`（全工具）；默认模型为会话模型；**步数不限**——除非 agent 定义里设置了 `steps`，或你用 `maxSteps` 覆盖（见 §7.2）。
- 返回子 agent 的最终文本（字符串）。

### 7.2 可选参数

```ts
await ctx.agent.run(prompt, {
  agent: 'plan',          // 用哪个 Agent 定义（只读规划集）
  model: 'agnes-2.5-pro', // 覆盖模型
  tools: ['read', 'grep'],// 显式白名单（覆盖 agent 配置；plan/plan-exit/task/question 永远排除）
                          // ✅ 可包含 'skill' 等内置工具 id 与 'mcp_xxx' 的 MCP 工具 id（配合 mcpServers）
  maxSteps: 8,            // 步数上限（I18）：覆盖 agent.steps；0/缺省 = 跟随 agent（留空=不限）
  mcpServers: ['fs'],     // MCP 服务器名单（I18）：并入这些服务器的工具（与该 Agent 生效名单取交集）；
                          //   传入后即使带 tools 白名单也可用 MCP 工具（白名单里写 mcp_* id 过滤）；缺省=旧行为
});
```

### 7.3 注意

- 子 agent 内的工具调用**同样走权限系统**（可以弹出权限卡）。
- 不可嵌套（子 agent 里不能再 `task`/`agent.run`）。
- token 用量计入会话统计；子 agent 未产出文本时返回空字符串，请自行兜底。
- 模型未配置 API Key 会 throw（`子运行模型不可用或未配置 API Key`）。

## 8. `ctx.ask` —— 主动征询用户

```ts
const ok = await ctx.ask({ tool: 'write', args: { file: '../outside/x.txt', content: '...' } });
if (ok === 'deny') return { skipped: true };
```

- 弹出与权限系统同款的确认卡；返回 `'allow' | 'deny' | 'allowAlways'`。
- 用途：对"语义上敏感但工具权限查不出来"的动作二次确认（删除、外发、覆盖式发布等）。
- 注意：`allowAlways` 对 `ctx.ask` 与本次 `ctx.tools` 调用语义一致（本次放行，不持久化）。

## 9. `ctx.signal` —— 中止感知

```ts
for (const f of files) {
  if (ctx.signal.aborted) { ctx.log('已停止，未处理：', files.slice(files.indexOf(f))); break; }
  await ctx.tools.read({ file: f });
}
```

- 点 ■ 停止或触发脚本超时 → `ctx.signal.aborted` 立即为 `true`；**正在 await 的 `ctx.tools.*` / `ctx.agent.run` 会 reject**（错误信息含"已停止"）。
- 脚本应在循环间隙检查并尽快 `return`；5 秒内优雅退出则按正常完成收尾，否则强杀。
- 同步 `while (true) {}` 死循环期间 JS 单线程被占死，abort 帧无法在脚本层响应——但**子进程会被真正 kill**（不再有旧版"杀不掉"的问题）。

## 10. 权限模型（脚本视角）

裁决顺序（与主会话模型完全一致）：

1. **agent 矩阵**：该会话 Agent 对工具的 加载（跟随全局/开/关）+ 权限（跟随全局/allow/deny/ask）覆盖；
2. **全局工具策略**（设置 → 权限矩阵）；
3. **内置默认**：read/grep/glob/webfetch/websearch/skill/多媒体类 = 放行；bash/write/edit/patch = 询问；`mcp_*` = 放行。

特例：

- **路径感知**：write/edit/patch 目标全部在 cwd 内 → 直接放行；有 cwd 外路径 → 弹卡。
- **bash 危险命令**（`rm -rf /`、`format`、`curl | sh`、`Remove-Item -Recurse` 等）无论矩阵如何都强制弹卡。
- `ctx.tools.question` / `ctx.tools.task` 被明确拒绝（主会话专用）；`plan/plan-exit` 对脚本不可见。

## 11. 错误处理

```ts
export default async function main(ctx) {
  const results = [];
  for (const f of ['a.txt', 'b.txt']) {
    try {
      results.push(await ctx.tools.read({ file: f }));
    } catch (e) {
      ctx.log('[跳过]', f, String(e));   // 单点失败不中断整批
      results.push(null);
    }
  }
  return results;
}
```

- 工具错误（文件不存在、权限拒绝、HTTP 非 2xx…）一律 **reject**，并已在消息流留下失败卡片。
- 顶层未捕获异常 → 消息流出现 **error 卡片**（`脚本进程异常退出…` 或脚本错误信息），已执行步骤保留。
- 建议：批量任务逐项 try/catch，把失败项收进返回值；重要节点 `ctx.log` 留痕。

## 12. 示例集

### 12.1 最小脚本

```ts
export default async function main(ctx) {
  ctx.log('你好，czagent！');
  return { ok: true, cwd: ctx.session.cwd };
}
```

### 12.2 统计报表（glob + bash + agent.run + write）

```ts
export default async function main(ctx) {
  const files = await ctx.tools.glob({ pattern: 'src/**/*.ts' });
  ctx.log(`发现 ${files.length} 个源文件`);

  // ⚠ 跨平台注意：Windows 会话 bash 工具走 PowerShell，类 Unix 走 bash——同一脚本在两类平台
  //   需要分支（ctx.session…/process.platform），或改用能跨平台的写法（如下方 find 的替代）。
  const cmd = process.platform === 'win32'
    ? `(Get-ChildItem -Recurse -Include *.ts -Path src | Get-Content).Count` // Windows PowerShell
    : `find src -name '*.ts' -type f | xargs wc -l | tail -1`;               // Linux/macOS bash
  const loc = await ctx.tools.bash({ command: cmd });

  const report = await ctx.agent.run(
    `这是一个 TS 项目的统计：文件 ${files.length} 个，总行数约 ${loc.trim()}。` +
    `请阅读 src/index.ts 并给出 3 条结构改进建议，中文，不超过 150 字。`,
    { maxSteps: 12 }, // 只读统计任务，限制步数防止发散
  );

  await ctx.tools.write({ file: 'report.md', content: `# 概览\n\n- 文件数：${files.length}\n- 行数：${loc.trim()}\n\n## 建议\n\n${report}\n` });
  return { files: files.length, report: 'report.md' };
}
```

### 12.7 node 内置库（fs / path / crypto）

```ts
import { createHash } from 'node:crypto';
import { promises as fs } from 'node:fs';
import path from 'node:path';

export default async function main(ctx) {
  // glob 返回换行分隔的路径清单
  const files = (await ctx.tools.glob({ pattern: 'src/**/*.ts' })).split('\n').filter(Boolean);

  const manifest = [];
  for (const rel of files) {
    const abs = path.resolve(ctx.session.cwd, rel); // resolve 同时兼容相对/绝对路径
    const buf = await fs.readFile(abs);
    manifest.push({
      file: rel,
      bytes: buf.length,
      sha256: createHash('sha256').update(buf).digest('hex'),
    });
  }

  // ⚠ 直接 fs：不经权限卡、消息流无卡片——适合中间产物/临时文件；
  //   正式改动建议走 ctx.tools.write（有权限确认与消息流记录）
  const out = path.join(ctx.session.cwd, 'checksums.json');
  await fs.writeFile(out, JSON.stringify(manifest, null, 2), 'utf8');

  ctx.log(`已写入 ${manifest.length} 条校验和 → checksums.json`);
  return { count: manifest.length, file: 'checksums.json' };
}
```

要点：内置库在子进程里**真实可用**（`node:fs`、`node:path`、`node:crypto`、`node:os`、`node:util`……）；路径一律以 `ctx.session.cwd` 为基准解析。

### 12.8 第三方库（zod 校验 + dayjs 命名）

```ts
import { z } from 'zod';   // ESM-only 包也 OK，bundle 直接解决
import dayjs from 'dayjs';

const Config = z.object({
  region: z.string(),
  replicas: z.number().int().min(1).max(16).default(2),
});

export default async function main(ctx) {
  const raw = await ctx.tools.read({ file: 'deploy.config.json' });

  const parsed = Config.safeParse(JSON.parse(raw));
  if (!parsed.success) {
    ctx.log('[配置无效]', parsed.error.issues.map((i) => `${i.path.join('.')}: ${i.message}`).join('; '));
    return { ok: false };
  }

  const cfg = parsed.data;
  const file = `deploy-${dayjs().format('YYYYMMDD-HHmmss')}.json`;
  await ctx.tools.write({ file, content: JSON.stringify(cfg, null, 2) }); // ✅ 走权限/卡片
  return { ok: true, file, region: cfg.region, replicas: cfg.replicas };
}
```

要点：第三方包从**工作目录的 node_modules** 解析（没装就先 `pnpm add zod dayjs`）；对照 12.7——正式产物这里用 `ctx.tools.write`，会弹权限/留下卡片记录。

## 13. 常见问题（FAQ）

**Q：脚本里能用 `node:fs` 和 npm 包吗？**
A：能。入口脚本在真实 node 子进程执行，模块无白名单（ESM-only 包由 bundle 解决）。但直接 `fs` 不经权限系统、消息流也无卡片，重要操作建议仍走 `ctx.tools`。

**Q：脚本会话的输入框/附件去哪了？**
A：I14.1 起已移除——脚本来源是工作目录文件，点 ▶ 即运行。要给脚本"喂数据"，把文件放进工作目录用相对路径引用即可。

**Q：点停止没反应/进程杀不掉？**
A：不存在了。停止会向子进程发 abort 并中断所有进行中的 `ctx.tools`/`agent.run`；5 秒宽限后**强杀进程**。纯同步死循环也逃不过 kill。

**Q：返回值/参数报"无法序列化"？**
A：跨进程边界只走 JSON：函数、Symbol、循环引用不可传/返回。把结果转成普通对象/字符串再 return。

**Q：怎么按用户设置分支（搜索条数、压缩开关、脚本超时等）？**
A：读 `ctx.settings.general`（只读快照）：如 `ctx.settings.general.websearch.maxResults`、`ctx.settings.general.compaction.auto`、`ctx.settings.general.scriptTimeoutMinutes`。注意其中**不含** Provider/API Key 信息；对象已冻结，改写无效。

**Q：单个工具卡住会拖死整个脚本吗？**
A：可以规避（I18）：`ctx.tools.xxx(input, { timeoutMs: 60_000 })` 对该次调用限时，超时即 reject（留失败卡片），脚本 catch 后可继续；未限时则跟随脚本整体超时（默认不限）。

**Q：为什么我的脚本报"未知或不可用的工具"？**
A：三种可能：① id 拼错（含连字符的要用 `ctx.tools['image-generate']` 方括号访问）；② 它是主会话/内部工具（`question`/`task`/`plan`/`plan-exit` 对脚本关闭）；③ MCP 工具——其服务器不在该会话 Agent 的生效名单里（查设置 → Agent 的 MCP 三态与全局启用）。注意：工具矩阵的"加载"开关不影响 `ctx.tools`。

**Q：子 agent 看得到主会话历史吗？**
A：看不到（隔离上下文）。需要背景就把结论写进 prompt，或给它工具让它自己读。

**Q：脚本抛 `用户拒绝了 xxx 操作`？**
A：权限卡被点了"拒绝"。批量任务请逐项 try/catch 决定跳过或中止（§11）。

**Q：bash 该写什么语法？**
A：Windows 会话内是 **PowerShell**（`Get-Content`/`Select-String`/`\\` 路径），Linux/macOS 是 POSIX。单命令超时 60s、输出过大会截断。

**Q：超长网页/长日志怎么处理？**
A：webfetch 正文超 2000 字符自动落盘，返回预览 + 路径，用 `ctx.tools.read` 分段读取；`ctx.log` 全量进消息流。

## 14. 安全与限制汇总

| 类别 | 规则 |
|---|---|
| 执行位置 | node 子进程；**信任模型 = npm run**：`fs`/网络/子进程不硬限制 |
| 推荐路径 | 文件/网络经 `ctx.tools`：权限系统 + 消息流卡片 |
| 危险命令 | bash 危险模式（`rm -rf /`、`shutdown`、`curl \| sh`、`Remove-Item -Recurse` 等）强制弹卡 |
| 超时 | 脚本默认**不限**（设置可调，0=不限；到期 abort + 5s 宽限 → kill）；bash 单命令 60s；`ctx.tools` 单次调用可用 `timeoutMs` 限时（I18） |
| 停止 | `ctx.signal` 即时感知；5s 宽限后真正终止进程 |
| 序列化 | `ctx` 跨进程调用参数与返回值必须可 JSON 序列化 |
| stdout | 被协议占用，直接写 stdout 的内容会作为日志行呈现 |
| 输出上限 | bash 超长输出截断；模型侧工具结果截断（DB 保留全量）；生成媒体上限 64MB |
| 不可用 | `question` / `task`（主会话专用）、`plan` / `plan-exit`（内部） |
| 已知边界 | native 插件依赖运行时 require，可能失败并透传 stderr；ESM-only 包经 bundle 可用但依赖动态 `require(变量)` 可能解析不到；`ctx.settings` 只含通用设置，不含 Provider/API Key |

## 15. 与主会话能力的边界

| 能力 | 主会话 | 脚本 |
|---|---|---|
| 调用全部工具/多媒体/MCP | ✅（模型决定） | ✅（你决定，经 `ctx.tools`） |
| 子 agent | ✅（`task` 工具） | ✅（`ctx.agent.run`，可配 `tools`/`mcpServers`/`maxSteps`） |
| 问用户 | ✅（`question` 工具） | ❌（脚本不能挂起问用户；用 `ctx.ask` 弹权限卡近似） |
| 任务清单面板 | ✅ | ✅（`ctx.tools.todo`） |
| 权限弹卡 | ✅ | ✅（同一套裁决） |
| 读设置项 | ✅（模型经工具间接感知） | ✅（`ctx.settings.general` 只读快照，I18） |

需要"问用户"的交互流程请放进对话会话；需要可复跑、可控、可版本化的流程放进脚本。
